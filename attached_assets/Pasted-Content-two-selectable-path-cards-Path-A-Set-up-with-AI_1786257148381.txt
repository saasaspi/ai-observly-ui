5. New Settings Tab: "Add-on Cost"

Location: New tab inside the existing Settings section, labeled "Add-on Cost."

Purpose: Let the user manually log additional costs that aren't automatically tracked (e.g., infra cost, third-party resource cost) and have those costs flow into ROI/margin calculations per feature.

UI — form fields for logging a cost:

Cost type (dropdown: e.g., Infra, Resource, Other — configurable list)
Amount + currency
Associated feature (dropdown — must map to an existing entry on the Features page)
Date incurred
Recurrence: one-time vs. recurring (if recurring, specify frequency — monthly/weekly)
Optional notes field

UI — below the form: a table listing all logged add-on costs (type, amount, feature, date, recurring flag) with edit and delete actions.

Business logic (critical — this is what makes the feature functional, not just a log):

When a cost is added, edited, or deleted, recalculate the associated feature's ROI and margin:
Feature Margin = Revenue attributed to feature − (existing tracked costs + logged add-on costs)
Feature ROI = (Revenue − Total Cost) / Total Cost
Recurring costs must be included in every subsequent period's calculation automatically until removed or ended, not just the period they were logged in.
These recalculated numbers must propagate to wherever ROI/margin is displayed — the Features page and any relevant Overview widgets — not just live in Settings.

Acceptance criteria:

Deleting a logged cost immediately reverts the affected feature's ROI/margin to reflect its removal.
A cost logged against a feature with no revenue data yet should not crash the calculation — handle divide-by-zero gracefully (e.g., show "N/A" for ROI until revenue exists).
