## 1. Page layout pattern (use this structure for all three pages below)

1. Hero: H1 + subheadline + primary CTA button + secondary text link, illustration on the right or as a background element.
2. A row of 3 feature cards (icon in a rounded square, bold title, 1–2 line description).
3. A large product-preview panel: a screenshot or embed of the relevant part of the AI Observly dashboard, with a caption underneath.
4. Four alternating sections: each one is a heading + paragraph + a CTA link on one side, and an image/screenshot on the other side. Alternate which side the image is on going down the page (image-right, then image-left, then image-right, then image-left).
5. A tabbed panel: 3 tabs for different personas, each tab showing a short headline, a paragraph, and a "learn more" link.
6. A small "Explore More Features" cross-link row pointing to the other two new pages (and the relevant free tool).
7. An FAQ accordion with 4 question/answer pairs.
8. A full-width footer CTA banner with a headline, one line of subtext, and a button.

Lines like `[IMAGE: ...]` below are placeholders describing what should go there —
use an existing dashboard screenshot if one is already in the project's assets,
otherwise use a simple styled placeholder graphic in the site's existing
illustration style. Do not leave a broken image tag.

## 2. CTA rule for all three pages — important

**Every single CTA button and link on these three pages must point to the pricing
page/section (`/pricing`)** — the hero primary CTA, every "View Pricing" link
inside the benefit sections, the footer CTA, and the product-preview CTA. None of
these three pages should link to the signup page. This is intentional: these are
bottom-of-funnel pages meant to push the reader toward Pricing, not straight to
signup.

The only exceptions are the "See how it works" secondary hero link (anchor-scrolls
down the same page) and the persona-tab and related-feature links (which point to
the other pages, as written below).

Reuse whatever CTA button component the rest of the site already uses — same
styling, same hover state. Don't create a new button style.

### FAQ
Q1: What is per-customer AI cost attribution?
A1: It's the practice of tracking exactly how much LLM/API spend each of your customers generates, instead of only seeing one combined provider bill. AI Observly automates this by rolling up usage per customer_id.

Q2: How is this different from Helicone or Langfuse?
A2: Helicone and Langfuse are developer-facing observability tools built around requests, latency, and errors. AI Observly is built specifically to answer one question for non-technical founders: which customers are profitable, and which ones aren't.

Q3: Do I need to add a proxy or change my code?
A3: No. AI Observly doesn't sit between your app and your LLM provider. You send a lightweight usage report from your existing code — no proxy, no rewritten API calls, no stored provider keys.

Q4: What do I see on the free plan?
A4: Your top 5 customers' cost, revenue, and margin, fully unlocked, on one provider. Every other customer name is still visible — the cost data just stays blurred until you upgrade.

Q4: Can I see feature cost trends over time?
A4: Yes — feature-level cost and usage trends are tracked over time so you can see whether a feature's cost is climbing faster than its usage or revenue.
